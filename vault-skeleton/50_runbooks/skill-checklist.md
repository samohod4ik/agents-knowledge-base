# Чеклист ревью новых скиллов

Перед выпуском нового скилла проверьте текст и поведение в реальном окружении.

## 1. Frontmatter

- [ ] Есть `name`.
- [ ] Есть `description`.
- [ ] `description` описывает поведение и триггеры, не абстрактную архитектуру.
- [ ] По `description` понятно, когда скилл должен загрузиться.

## 2. Структура

- [ ] `SKILL.md` лежит в корне скилла.
- [ ] `scripts/` вынесены отдельно от описания.
- [ ] `references/` содержит только частные сценарии.
- [ ] `assets/` содержит шаблоны, не секреты.
- [ ] `config/` не содержит секреты открытым текстом.
- [ ] `cache/` только для временных данных.

## 3. Ясность поведения

- [ ] В начале сказано, что делает скилл.
- [ ] Понятно, когда звать и когда не звать.
- [ ] Нет кода там, где должна быть логика.

## 4. Проверка окружения

- [ ] Есть шаг `doctor`.
- [ ] Проверяются зависимости и, если нужно, сеть.
- [ ] Есть понятная ошибка, если окружение не готово.

## 5. Деградация

- [ ] Описан fallback (например, правки vault на диске без MCP).
- [ ] Понятно, что делать при отсутствии CLI.

## 6. Регистрация в vault

- [ ] Заметка `60_skills/<owner>/<skill-name>.md` создана в том же ходе.
- [ ] Связи в `## Related` без self-link.
- [ ] Пути внутри скилла — `<VAULT>` и `<SKILLS_ROOT>`, не чужой абсолютный диск.
